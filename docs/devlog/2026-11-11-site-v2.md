# 官網 v2：多頁、四語系、預覽環境

## 11:54 — 改用 Eleventy

**決策**：從單頁純 HTML 改成 Eleventy，6 頁 × 4 語系由同一份版面產生，文字放 `src/_data/i18n/*.json`。

**Why**：24 個頁面如果手寫，改一句話要改 4 個檔，很容易漏。i18n JSON 讓翻譯可以分給不同人平行處理，用 `check-i18n` 擋住結構不一致。

**替代方案**：Astro 功能更多，但這個網站沒有互動元件，Eleventy 依賴少、建置快；純 HTML 複製四份則維護成本太高。

**結論**：繁中為主稿，其他語系 key 必須與繁中完全相同，部署時檢查。

## 12:00 — 內容分工與事實把關

**決策**：事業項目與公司沿革各派一個 sub-agent 從簡報整理初稿，定稿後再派三個 sub-agent 平行翻譯。

**Why**：素材分散在多份 pptx/pdf；翻譯三語彼此獨立。檔案所有權切開（各 agent 只寫自己的檔），不會互相覆蓋。

**替代方案**：自己串行寫完再翻，時間約三倍。

**結論**：初稿合併時修掉了不符事實的說法：智聖 2026 年才成立，不能寫「長期投入」；英格索蘭的「領導品牌」改成較保守的說法；彰京開發是關係企業，不列為合作品牌。

## 12:20 — 預覽環境用獨立 repo + 子網域

**決策**：預覽站放在 `D-SENG-TECH/official-website-dev`，網址 `dev.d-seng.com.tw`，同一份 workflow 依 repo 名稱判斷是否為預覽站。

**Why**：GitHub Pages 一個 repo 只能有一個網站；子網域讓網站維持用根目錄路徑（`/assets/...`），不必處理子路徑。

**替代方案**：Cloudflare Pages 或 Netlify 的 branch preview 更方便，但要多開一個平台帳號；GitHub Pages 的子路徑（`/official-website-dev/`）會讓所有絕對路徑失效。

**結論**：預覽站加 `noindex` 與 `robots.txt`，頁尾顯示 `DEV`。正式站仍只從 `official-website` 的 `main` 部署。

## 13:10 — 事業項目拆成獨立頁面

**決策**：每個事業項目一頁（`/business/{slug}/`），`/business/` 改成總覽卡片加營運項目；選單的下拉與首頁卡片都直接連到各頁。

**Why**：公司要求各事業項目獨立呈現；獨立頁面也有各自的標題與描述，搜尋引擎可以分別收錄。

**替代方案**：同一頁用錨點分段，維護簡單，但不符需求。

**結論**：用 `_data/business_pages.js` 把語言 × 項目攤平成 24 頁，網址 slug 由 id 的 `_` 換成 `-` 產生。新增項目只要在 i18n 的 `business.items` 加一筆。

## 14:40 — 正式 Logo 改用 SVG

**決策**：頁首用橫式 SVG，頁尾用黑底版 SVG（裁掉四周留白），favicon 從橫式檔裁出 S 圖形；頁尾公司名稱兩行依使用者要求拿掉，替代文字改放在 Logo 上。

**Why**：SVG 在高解析度螢幕不會糊，也不必維護多種尺寸的 PNG。

**結論**：直式 Logo 先放在 `src/assets/logo-vertical.svg` 備用（印刷品、下載專區）。

## 15:20 — 事業項目內容擴充與彰京故事

**決策**：每個事業項目新增 `sections`（3–4 個小標＋說明＋條列），由三個 sub-agent 依資料夾分工整理初稿，再由協調者審稿、合併後派三語翻譯。彰京開發從卡片改成故事章節＋基本資料，首頁加一個短版區塊連到 `/about/#affiliates`。

**Why**：使用者認為內容太少；資料散在多份簡報與型錄，按資料來源切分最不會重複讀檔。

**替代方案**：把所有細節塞進 `body` 段落，結構簡單但頁面變成長文、難以瀏覽。

**結論**：審稿時刪掉沒有來源的說法（空壓機的噪音監測、工具機光學追焦、監測工程裡借用氣體系統教材推論的項目、彰京客戶群推論）；簡報中的資本額、營業額、庫存金額、員工數與客戶 logo 一律不放。關係企業只保留彰京開發。

## 17:40 — AI 監測頁改為移植原版介紹簡報

**決策**：放棄自己簡化做的六步流程，改把業主提供的監測簡報原始碼中可公開的頁面逐一移植成 Eleventy 區塊：開場捲動敘事、客戶痛點、訊號、解法、八個監測畫面、甜蜜點。

**Why**：使用者認為簡化版品質落差太大；原版的版面、動畫與資訊密度才是要呈現的樣子。

**替代方案**：iframe 嵌入原站——整頁是他牌品牌、有客戶案例與損失金額、還有 GA，不符合官網規則；把整個 Next.js 專案靜態匯出——依賴 three.js 與外部 3D demo，維護成本高。

**結論**：沿用原版 `--cc-*` token 名稱、換成智聖色系（`src/assets/aimon/tokens.css`），每個區塊各自一組 njk/css/js/json，四個 sub-agent 依檔案分工平行移植。3D 畫面改用靜態截圖；他牌自稱、客戶與廠區名稱、真實案例照片、火災損失金額、他牌介紹頁與試用 QR 都不移植。
