# 公司介紹靜態網站

## 15:10 — 公開內容的取捨

**決策**：只用公司海報文案、實際營運項目、組織表與登記地址；內部 PDF 與會議紀錄不進 repo。

**Why**：來源 PDF 含身分證、存摺、股權；會議紀錄含客戶訂單、毛利與併購討論，都不該公開。

**替代方案**：把會議中提到的客戶與裝機數量當實績放上去，說服力較高，但未經公司同意公開，不採用。

**結論**：事業項目的敘述只保留能力描述。實績要等公司確認可公開後再加。

## 15:15 — 組織表用巢狀清單做

**決策**：組織表用 `ul/li` 加 CSS 連接線，窄螢幕改成縮排清單。

**Why**：人事常異動，文字改一行就好，也利於手機閱讀與 SEO。

**替代方案**：直接放 PDF 截圖，最快但手機上看不清楚，每次異動都要重新出圖。

**結論**：採巢狀清單。PDF 左下角的內部註記（人力需求、會議室名單）不放。

## 11:01 — 拿掉組織架構（2026-11-04）

**決策**：依公司要求，從公開網站移除整個組織架構區塊、選單連結與相關 CSS。

**Why**：組織表含員工姓名與人數，公司決定不對外公開。

**替代方案**：改成只列部門與職稱、不列姓名，但公司要求整段拿掉，不採用。

**結論**：之後若要恢復，可從 git 歷史取回 `section#org` 與 `/* Org tree */` 那段 CSS。
